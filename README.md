# videye
A video processing program to extract annotations.

Run it with input and text output paths. `--game gt` selects Ghost of Tsushima (the default), while `--game er` selects Elden Ring. Add `--vout` to also write an annotated video. The in-process Tesseract library backend is used by default; pass `--use-tesseract-library false` to use the subprocess backend:

```sh
cargo run -- --in inputfile --out outputfile [--game gt|er] [--vout annotated.mp4] [--parallel-count 16] [--skip n] [--dedupe seconds] [--use-tesseract-library true|false]
```

Frame processing uses sixteen worker threads by default; set `--parallel-count` to change the number of concurrent workers. `--skip n` processes one frame then skips the next `n` frames; it defaults to `0`. Legacy detection deduplication is disabled by default by the internal `dedup_mode_1` boolean in `src/processing.rs`. Setting it to `true` restores the legacy deduplication behavior before the new post-processing pass. `--dedupe seconds` sets the legacy mode's deduplication window and defaults to `120` seconds; it has no effect while that mode is disabled. Frame numbers and timestamps remain based on the original input, and skipped frames are included in the reported FPS. The video output supports MP4, Matroska (`.mkv`), and WebM (`.webm`) files.

The new post-processing deduplication pass is enabled by the internal `dedup_mode_2 = true` setting in `src/processing.rs`, with `dedup_seconds = 0.25` and `dedup_repeat_seconds = 15`. After video processing and before either history format is written, it groups consecutive detections with identical types and exact text (both act number and title for acts). A group whose last-to-first timestamp span is at least `dedup_seconds` retains only its first entry; shorter groups, including single detections, are discarded. Before retaining a qualifying entry, it compares that entry only with the newest entry already retained. If their types and text match and their timestamps are less than `dedup_repeat_seconds` apart, the candidate is discarded; an entry exactly 15 seconds later is retained. Discarded entries do not reset this repeat window. Groups are not joined across intervening entries with different types or text, and skipped frames do not change source timestamps. Setting `dedup_mode_2` to `false` bypasses this pass. The legacy `dedup_mode_1` remains disabled.

Console progress messages report every 10% of input read, from 10% through 100%, using source frame numbers (including skipped frames). The total frame count is estimated from the video's duration and frame rate, so intermediate percentages may be approximate for variable-frame-rate input. The 100% message is emitted only at end of input, before any remaining worker results finish processing.

Detectors reject failed prerequisites before doing dependent work. Act detection validates both crops before OCR and only reads the title after the act number succeeds. Story detection stops before scanning the rest of the panel when no valid top rule can exist. Icon-box detection checks one border at a time and rejects a candidate as soon as the remaining samples cannot meet that border's threshold. Place and invaded banners stop when too few remaining columns could supply the required edge or band support, and NewItem stops sampling a separator row once its support threshold is unreachable. These shortcuts preserve the existing match thresholds and candidate ranking; searches still examine all candidates that could affect the result. Combat1 retains its shared gray/red scan because separating it into stages measured slower.

An optional Act OCR-stage benchmark uses the local sample and compares interleaved median timings for the previous eager sequence and the fail-fast sequence, with matching, missing-number, and missing-title inputs. Successful OCR results are warmed in separate caches for each sequence; this is not an end-to-end video FPS benchmark:

```sh
timeout 60s cargo test --release benchmark_act_detector -- --ignored --nocapture
```

After editing a text output file externally, recalculate its real and cosmetic timestamp separators in place:

```sh
cargo run -- --retime outputfile
```

The first timestamp is real (`:`); later timestamps are real when at least 10 seconds have elapsed since the last real timestamp, and cosmetic (`։`) otherwise. Retiming uses displayed whole seconds because the output does not store a frame rate. Frame suffixes, text, whitespace, and non-timestamp lines are preserved; entries are not sorted and a begin marker is not added. The file is replaced only after all timestamps have been validated and the rewritten content has been saved successfully. `--retime` does not require video input and cannot be combined with `--in`, `--out`, or `--vout`.

Replacement first attempts to preserve permissions, sync the completed temporary file, and rename it over the original. If any of those operations fail (for example, permission setting returns "Operation not supported" on a GVfs remote mount), Videye emits a warning identifying the failed operation and falls back to opening and truncating the original file, copying the temporary file's contents into it, and syncing it. This fallback preserves the original file's permissions but is not atomic: interruption or a write failure can leave a partial file. If both methods fail, the error reports both failures. Temporary files are cleaned up after either method.

Elden Ring mode also has a `place1` detector for region-name banners such as `samples/limgrave.png`, where the text sits on a translucent dark band whose darkness depends on the scene. At sixteen columns it looks for the band's bottom edge (dark band, gray underline, brighter scene), then the top edge (brighter scene above the dark band), then near-white text strokes across the middle of the lower-case letters. Frames where the text is still fading in or out are skipped. The crop sent to OCR extends below the underline so descenders like the `g` are kept, and for place1 it is widened by 10% (5% per side) so the first and last letters are not cut off; scenery below the band that is not connected to the letters is removed. Matches are reported as `place1: <name>`. `place2` uses the same banner detector at the place2 screen position, with its narrower banner; matches are reported as `place2: <name>`. A `place3` detector uses the same approach for the smaller location banners that sit higher in the frame, such as `samples/elleh_p.png`; its matches are reported as `place3: <name>`. `place2`, `place1`, and `place3` are separate history types; when `dedup_mode_1` is enabled, duplicates are only suppressed within the same type. With the local sample available, `cargo test place1 -- --include-ignored` also checks `samples/limgrave.png` using both OCR backends.

Elden Ring mode uses the same icon-box detector for sites of grace and merchants. After detecting the box, it classifies the icon from the brightness coverage in its lower interior, then OCRs the adjacent name and records a grace or merchant entry. The icon box at the top left has soft edges, so besides a coarse grid search the detector also tries the exact positions where the box edges appear in brightness profiles. The OCR region ends at the first gap wider than the label height after the name, so bright scenery to the right is not read as text.

Elden Ring mode emits `newitem: <item name>` after detecting the three gray separators in the lower-center item popup and confirming `NEW` with OCR. Item names have a separate UTF-8 character filter supporting alphanumerics, accented characters, commas, dashes, apostrophes, and square brackets. Existing match character filters are unchanged. With the local sample available, run `cargo test newitem -- --include-ignored` to also check `samples/lizard.png` using both OCR backends without processing the sample video.

Elden Ring mode has a `system` detector for the System menu, such as `samples/system.png`. It looks for the same kind of icon box as grace and merchants, but near the top-left corner of the frame, and confirms the adjacent `System` label with OCR. It then OCRs the menu tab heading below and records a `system` entry only when the heading is `Camera Options`; other tabs are ignored. Entries are deduplicated like the other types and are written two spaces after the timestamp. With the local sample available, run `cargo test system -- --include-ignored` to also check `samples/system.png` using both OCR backends.

Elden Ring mode has an `invaded` detector for the multiplayer message banner low in the frame, such as `samples/invaded.png`. It looks for a translucent dark band across the middle half of the frame, with a grey line along its bottom and brighter scenery above its soft top edge. It then finds the bright, centred text, which may be about twice as wide as the sample, and OCRs it. The OCR also accepts sentence punctuation such as `!`. The recognized text, for example `Invaded by Millicent!`, is stored as an `invaded` entry. Messages containing `Summoning cooperator`, `has died`, or `has returned to their world` are not saved (case-sensitive substring matching). Entries are deduplicated like the other types and are written two spaces after the timestamp. With the local sample available, run `cargo test invaded -- --include-ignored` to also check `samples/invaded.png` using both OCR backends.

The default in-process backend requires the Tesseract and Leptonica development libraries, Clang/libclang, GStreamer development libraries, and English language data. On Ubuntu or Debian, install them with `sudo apt install libtesseract-dev libleptonica-dev clang libclang-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev tesseract-ocr-eng`. A native Tesseract crash in library mode can terminate Videye; use the subprocess backend to contain such crashes to the OCR child process.

With `--skip`, GStreamer drops skipped decoded frames before RGBA conversion, reducing conversion work and frame-buffer traffic while preserving source frame numbers and timestamps. Inter-frame codecs may still need to decode skipped frames to reach later frames.
